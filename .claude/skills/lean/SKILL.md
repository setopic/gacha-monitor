# 書かずに済む道を探す

**足す前に、足さずに済むかを確かめる。** 書いたコードは、読む・直す・消す手間を持ち続ける。

このスキルは
[dietrichgebert/ponytail](https://github.com/dietrichgebert/ponytail) を、
このプロジェクトに合わせて作り直したもの。

**決定の梯子（7 段）と、削らないものは原典と同じ。** 違うのは 4 点である。

| | 原典の `ponytail` | このスキル |
| --- | --- | --- |
| 原則の置き場所 | スキルと `AGENTS.md` | **META-06**（`docs/00-meta/principles.md`）。このファイルは手順だけを持つ |
| 強度のモード | `lite` / `full` / `ultra`（hooks が保持する） | **持たない** |
| 先送りの印 | `ponytail:` コメントと、それを集める台帳 | **既にあるコメントの決まり**（「なぜやらなかったか」を書く） |
| 実行時の依存 | Node（hooks） | **無い** |

**原典が入っていなくても動く。** 要るものはこのリポジトリの中にある。
テンプレートが公開リポジトリで、ponytail を入れていない利用者がいるためである。
**`Skill` 呼び出しに委譲しない。**

**モードを持たないのは、状態を保てないからである。** 原典は hooks でモードを覚えている。
hooks を持ち込まない以上、モードは会話の中の言葉にしかならず、次のセッションに残らない。

## いつ使うか

| 場面 | 合図 |
| --- | --- |
| **実装に着手する前** | 新しいモジュール・クラス・依存を足そうとしている |
| **差分を出す前** | 差分に新しいファイルが増えた。コミットや PR の直前 |

**`/grill` の後に回す。** 何を作るかが決まっていないと、
梯子の 1 段目（そもそも要るか）に答えられない。要件が曖昧なら先に `/grill`。

## 着手する前: 梯子を登る

### 1. 原則を読む

**毎回 `docs/00-meta/principles.md`（META-06）を読む。**
梯子・削らないもの・過剰な実装の兆候は、そちらにしか書いていない。

### 2. 問題を理解する

**登る前に読む。** 課題と、それが触るコードを読み、実際の流れを端から端まで追う。
規定しているノードの近傍と、その `implemented_by` の指し先を読む。

```bash
python -m tools.graph render --format json --focus <ID> --depth 1
```

### 3. 上から順に当てる

**1 段目から当て、最初に止まった段で終える。**

- **2 段目（既にあるか）は探してから答える。** 「たぶん無い」で新しく書くと、
  似たものが 2 つになる

  ```bash
  git grep -n "<それらしい名前>"
  ```

- **3〜5 段目は、入っているものを確かめてから答える。** 依存の一覧
  （`requirements.txt`、`package.json` など）を読む。標準ライブラリの機能は、
  **実際に回している版**にあるかを見る

### 4. 止まった段を示してから書く

書き始める前に、**どの段で止まったか**を 1 行で示す。

```
梯子: 3 段目で止まった。標準ライブラリの zoneinfo で足りる。依存は足さない。
```

**7 段目まで来たときだけ、新しいコードを書く。** そのときも動く最小のものにする。

**依頼の一部が要らないと思ったら、書く前に聞く。** 黙って削らない。
依頼された機能を落とすのは簡略化ではなく、仕様の変更である。

## 差分を出す前: 読み返して削る

```bash
git diff
```

**META-06 の「過剰な実装の兆候」の表を、差分に上から当てる。**
当たったものは削る。残すなら、梯子の 1 段目に戻って要る理由を言えること。

**次に「削らないもの」の表を当てる。** 削りすぎていないかを見る。
入力検証やエラー処理は、差分が長くなっても残す。

**簡略化した箇所には、限界と、引き上げる条件を書く。**
書き方は META-06 の「書かなかったものを残す」にある。

## 報告の形

**コードを先に、説明は短く。** 省いたものは 1 行で書く。

```
省いたもの: キャッシュ。同じ値を 2 度読む箇所が無い。遅くなったら足す。
```

**会話に書いただけでは消える。** 「足す条件」は、コードのコメントか ADR にも残す。

## やってはいけないこと

- **理解する前に登る。** 最短の差分が、間違った場所の差分になる
- **削らないものを削る。** 梯子は何を書かないかを決める道具で、守りを外す道具ではない
- **依頼を黙って削る。** 要らないと思うなら、書く前に聞く
- **2 段目を推測で済ませる。** 探してから答える
- **読めない 1 行を書く。** 6 段目は読める 1 行のことである。
  賢い 1 行より、退屈な数行のほうが良い

## 終わる条件

- [ ] 止まった段を示した
- [ ] 差分に「過剰な実装の兆候」が残っていない（残したなら、要る理由を言える）
- [ ] 「削らないもの」を削っていない
- [ ] 簡略化した箇所に、限界と引き上げる条件が書いてある
- [ ] 自明でないロジックに、動くことを確かめる検査が 1 つある
- [ ] 文書を触ったなら `check` が通る
