# 文書と実装を同じリポジトリに置く

`graph-doc-template` は文書だけを扱う。**こちらは実装も同じリポジトリに置く型**である。

## なぜ分けないのか

**分けても 1 つのプロジェクトとして動いてしまうから。**

実データで測った結果がこれである。

| 実装 | 文書 id を参照するコミット | 参照した id | 実在しなかった |
| --- | --- | --- | --- |
| tournament | **85 / 89（95%）** | 97 種 | 0 |
| medieval-idle | **8 / 8（100%）** | 17 種 | 0 |

**繋いでいたのは手書きのコミットメッセージだけだった。**
`ADR-0065` と書いてあることを確かめているものは何も無く、
逆向き（文書を変えたのに実装が動いていない）は誰も見ていなかった。

同じリポジトリにすると 3 つが手に入る。

1. **1 つのコミットに文書と実装が入る。** リポジトリを跨ぐと原理的にできない
2. **`implemented_by` で対応を宣言でき、`G016` / `G017` が確かめる**
3. **用語表（`G013`）が実装の文言に届く。**
   実際に「すでに参加登録済みです。」という**実装側の欠陥**を用語表が捕まえたことがある

## 置き方

```
docs/            設計文書（グラフ）        テンプレートが配る
tools/graph/     検証ツール                テンプレートが配る
.github/
  workflows/
    graph-check.yml   文書の検査           テンプレートが配る。書き換えない
    app-check.yml     実装の検査           プロジェクトのもの（merge=ours）
<実装>/          ソース                    名前は自由
```

**実装のディレクトリ名は決めない。** `src/` でも `tournament/` でもよい。
`docs/` と `tools/graph/` だけが予約されている。

## 対応の粒度

層によって違う。**測ってから宣言する。**

| 層 | 実装との対応 | 宣言 |
| --- | --- | --- |
| ドメイン | ほぼ 1 対 1（チーム → `teams.py`） | **書く** |
| 契約 | 多対少（画面を作るモジュールが全契約に共通で現れる） | 書く |
| ユースケース | 契約と重なることが多い | 対応が明確なときだけ |
| アーキテクチャ / ADR | 対応するファイルが無いことが多い | **書かない** |

**全ノードに書かない。** 無理に書くと、実装を触るたびに関係の無い ADR が
`G017` に挙がる。

## 要件は issue から始める

| 段階 | どこに書くか | 残るか |
| --- | --- | --- |
| 何が困っているか、何を決めるか | issue | **流れる** |
| なぜその判断にしたか、却下した案 | ADR | 残る |
| 振る舞いと受け入れ条件 | ユースケースの「受け入れ条件」 | 残る |
| 概念と言葉 | ドメインノードの「定義」「用語」 | 残る |
| 実装 | ソース（`implemented_by` で指す） | 残る |

**issue を実装計画の置き場にしない。** 受け入れ条件はユースケースが持ち、
決定は ADR が持っている。**issue に同じものを書くと 2 箇所を保つことになる。**

issue が持つのは**まだ答えが無い問い**だけである。答えが出たら文書へ移す。

**ここが決めているのは「どこに書くか」だけである。**
いつ何をするか（順番・関門・`grill` を回す場面）は [META-05](./dev-flow.md) にある。

## 既にある実装を合流させる

**文書リポジトリが実装を取り込む向きにする。**
文書側がテンプレートの系譜と `.gitattributes` の `merge=ours` を持っているので、
逆向きにすると共有ファイルを手で揃えるブートストラップが要る。

```bash
git remote add impl <実装リポジトリ>
git fetch impl
git merge impl/main --allow-unrelated-histories
```

**履歴は両方とも残る。** 取り込んだ後、元の実装リポジトリは読み取り専用にする。

合流したら `implemented_by` を書き、`check` を回す。
`G016` が指し先の間違いを、`G017` が片側だけの変更を落とす。
