# 開発の原則

**書く前に、書かずに済む道を探す。** いちばん良いコードは、書かなかったコードである。

これは [ponytail](https://github.com/dietrichgebert/ponytail) の決定の梯子を、
このテンプレートの語彙で書き直したもの。**本家が入っていなくても効く。**
本家のプラグインを入れている環境では併用してよい。

**強制はしない。** 過剰な実装は `check` では測れない。
`review` の `A008`・`A009`（[META-03](./ai-review.md)）が見るのは文書だけで、
コードには届かない。**手順は `/lean` スキル（`.claude/skills/lean/SKILL.md`）にある。**

## 決定の梯子

**上から順に当て、最初に止まった段で終える。**

| 段 | 問い | 止まったら |
| --- | --- | --- |
| 1 | **そもそも要るか**（YAGNI） | 書かない。要る理由を言えないなら、要求がまだ無い |
| 2 | このリポジトリに既にあるか | それを使う。似たものを 2 つにしない |
| 3 | 標準ライブラリにあるか | それを使う |
| 4 | 実行環境の機能で済むか | それを使う（OS の機能、GitHub の組み込みの自動化など） |
| 5 | 既に入っている依存にあるか | それを使う。**依存を足すのは最後** |
| 6 | 1 行で書けるか | 1 行で書く |
| 7 | ここまで来たら | **動く最小のコードを書く** |

**登る前に、問題を理解する。** 課題と、それが触るコードを読み、
実際の流れを端から端まで追ってから登る。**理解しないまま最短の差分を選ぶと、
間違った場所を直して、別の不具合を作る。**

## 削らないもの

**梯子は「何を書かないか」を決める道具で、次を削る道具ではない。**

| 削らないもの | なぜ |
| --- | --- |
| 信頼の境界での入力検証 | 外から来た値は、壊れていることを前提にする |
| データを失わないためのエラー処理 | 失ったデータは戻らない |
| セキュリティ | 後から足すと、足すまでに出した版がすべて穴を持っている |
| アクセシビリティ | 使えない人が出ても、作った側の画面では気付けない |
| 明示的に依頼された機能 | 依頼を削るのは簡略化ではなく、仕様の変更である |

## 過剰な実装の兆候

**次を書いていたら、梯子の 1 段目に戻る。**

| 兆候 | 代わりに |
| --- | --- |
| 実装が 1 つしか無いインターフェース・基底クラス | 具体を直接書く。2 つ目が来たときに切り出す |
| 作るものが 1 種類しか無い factory | 直接作る |
| 誰も変えない設定項目 | 定数にする |
| 呼ばれていない引数・分岐 | 消す |
| 「将来に備えて」の拡張点 | 書かない。要求が来たときに足す |
| 呼び出し側を 1 つずつ直す修正 | 共有している側を 1 か所で直す |

**消すことは、足すことより先に考える。** 退屈で正しいコードは、賢いコードより良い。

文書に現れた同じ兆候は、`review` の `A008`・`A009` が見る。

## 書かなかったものを残す

**削った判断は、読んだだけでは見えない。** 次に来た人（AI を含む）が
「足りない」と思って足し直す。だから残す。**置き場所は既にある。**

| 何を | どこに |
| --- | --- |
| コードで簡略化した箇所の限界と、引き上げる条件 | **コメント**（`CLAUDE.md` の「コメントには『なぜやらなかったか』を書く」） |
| 設計として見送った案 | **ADR の「却下した案」** |
| 先送りした要求 | ユースケースやドメインノードの本文に**「やらない」と書く** |

コメントは**限界と、引き上げる条件**の 2 つを書く。

```python
# 全件を毎回読む。数百件までは問題にならない。
# 1 万件を超えたら索引を作る。
```

**本家の `ponytail:` コメントと、それを集める台帳は入れていない。**
「なぜやらなかったか」を書くコメントの決まりが既にあり、それで足りるためである。

## 検査を 1 つ残す

**自明でないロジックを書いたら、動くことを確かめる検査を 1 つ残す。**
網羅は要らない。1 行で済むものには要らない。

実装の検査は `app-check.yml` で回す（[META-04](./implementation-layout.md)）。

## grill との分担

| | `/grill` | `/lean` |
| --- | --- | --- |
| 決めるもの | **何を作るか** | **どれだけ少なく作るか** |
| いつ | 書き始める前（[META-05](./dev-flow.md)） | 実装に着手する前と、差分を出す前 |
| 残るもの | ADR・受け入れ条件・用語表 | 書かなかったコードと、その理由のコメント |

**順番は grill が先である。** 何を作るかが決まっていないと、
梯子の 1 段目（そもそも要るか）に答えられない。
