# 注目商品を検知して通知する

## 概要

| 項目 | 内容 |
| --- | --- |
| アクター | 販売店の担当者（受け手。操作はしない） |
| きっかけ | 1 日 1 回の時刻起動 |
| 価値 | 発売前に注目商品が分かり、整理券・抽選・入荷調整・人員配置を準備できる |

## 事前条件

- [ ] 設定シートに監視対象が入っている
- [ ] 設定シートの稼働が有効になっている
- [ ] X API の認証情報と残高がある
- [ ] 担当者が LINE 公式アカウントを友だち追加している

## 基本フロー

1. 設定シートから監視対象・追跡期間・閾値 3 段階を読む
2. 追跡期間内に投稿されたものを取得する（[[CON-01]]）
3. 自作でない投稿を除く（[[DOM-01]]）
4. 残った投稿を日次スナップショットに 1 行ずつ追記する（[[CON-03]]）
5. 通知ログから、投稿ごとに**通知済みの最大段階**を読む
6. 保存数が到達している最大の段階が、通知済みの段階より上の投稿を集める
7. 集まった投稿を保存数の多い順に 1 通へまとめて送る（[[CON-02]]）
8. 送れた投稿を通知ログに追記する

## 代替フロー

| 分岐 | 条件 | 振る舞い |
| --- | --- | --- |
| A1 | 段階を超えた投稿が 1 件も無い | **何も送らない。** 通知が来ないこと自体は正常。生存確認は [[UC-02]] が担う |
| A2 | 追跡期間内の投稿が 1 回の取得上限を超える | 続きを取得する。上限に達したら取りこぼしの可能性として [[UC-03]] に渡す |
| A3 | 1 通に載る件数を超えた | 上位だけを載せ、残りは件数だけ伝える。全件は日次スナップショットに残る |

## 例外フロー

| 例外 | 条件 | 振る舞い | 対応するエラー |
| --- | --- | --- | --- |
| E1 | 取得が失敗した | 記録して知らせ、処理を止める。次回の実行で再開する | [[UC-03]] |
| E2 | 取得できた投稿が 0 件 | 異常として知らせる。監視対象が沈黙しているだけの可能性もあるが、区別できない | [[UC-03]] |
| E3 | 取得できた全投稿の全指標が 0 | 異常として知らせる。取得元の障害を疑う | [[UC-03]] |
| E4 | 通知の送信が失敗した | 通知ログに書かない。**次回の実行で同じ段階を送り直す** | [[UC-03]] |

## 事後条件

- [ ] 追跡期間内の自作投稿すべてについて、その日の指標が日次スナップショットにある
- [ ] **同じ投稿の同じ段階は二度通知されない**
- [ ] 通知ログに残っている投稿は、必ず送信に成功している
