# 異常と予算超過を知らせる

## 概要

| 項目 | 内容 |
| --- | --- |
| アクター | 販売店の担当者（受け手） |
| きっかけ | 日次の処理の中で異常を検知したとき、または月の利用額が警告の割合を超えたとき |
| 価値 | **止まったことに気づける。** 前払いの残高が尽きると、この仕組みは黙って停止する |

## 事前条件

- [ ] LINE への送信ができる

## 基本フロー

1. 日次の処理の中で、次のいずれかを検知する
   - 取得が失敗した（認証切れ・残高不足・接続エラー）
   - 取得できた投稿が 0 件
   - 取得できた全投稿の全指標が 0
   - 取得が 1 回の上限に達した（取りこぼしの可能性）
2. 通知ログに異常として記録する
3. 内容を担当者へ送る（[CON-02](../40-contracts/con-02-line-notify.md)）
4. 月の利用額が予算の警告割合を超えていれば、あわせて知らせる

## 代替フロー

| 分岐 | 条件 | 振る舞い |
| --- | --- | --- |
| A1 | 同じ月に予算警告を既に送っている | **送らない。** 超えた翌日から毎日鳴ると警告として機能しなくなる |
| A2 | 月が変わった | 今月の取得件数を 0 に戻してから数え直す |

## 例外フロー

| 例外 | 条件 | 振る舞い | 対応するエラー |
| --- | --- | --- | --- |
| E1 | 通知ログへの記録が失敗した | 握りつぶして送信は試みる。**元の異常を埋もれさせない** | — |
| E2 | 送信も失敗した | 握りつぶし、最後に元の異常を投げ直す。実行基盤の失敗通知に委ねる | — |

## 事後条件

- [ ] 検知した異常は通知ログに残っている
- [ ] **元の異常が、二次的な失敗によって握りつぶされていない**
- [ ] 予算警告は同じ月に 1 回しか送られていない

## 検知できないもの

**残高が尽きる前の予告は出ない。** 残高の事前警告は入れていないため、
気づけるのは実際に取得が失敗した時点になる。当日中には分かるが、
止まる前には分からない。
