# 閾値を 3 段階にする

- 日付: 2026-09-10
- 状態: stable

## 背景

当初は「閾値を 1 つ置き、超えたら 1 回通知する」だった。
これだと、閾値をわずかに超えた投稿と、10 倍に化けた投稿が同じ扱いになる。
販売店にとってこの 2 つは打ち手が違う。

一方で、段階を細かくすると同じ投稿が何度も届いて通知が読まれなくなる。

## 決定

**閾値を 3 段階（500 / 1,000 / 2,000）置き、上の段階に届くたびに 1 回ずつ通知する。**
1 つの投稿につき最大 3 回。同じ段階では二度通知しない。

2 段階目に `【要チェック】`、3 段階目に `【要注意！！】` を本文の先頭に付ける。

## 理由

**通知の中身を保存数と投稿の場所だけに絞ったため、印が無いと続報を見分けられない。**
同じ場所を指す通知が 1 週間後に届いても、新着なのか続報なのか判断できなくなる。
段階ごとに印を変えれば、4 文字増やすだけで見分けがつく。

実測での通知量は次のとおり（91 件・5 日ぶんから換算）。

| 閾値 | 該当 | 1 日あたり |
| --- | --- | --- |
| 500 | 26 件 | 5.2 件 |
| 1,000 | 11 件 | 2.2 件 |
| 2,000 | 6 件 | 1.2 件 |
| **合計** | — | **8.6 件** |

「1 日に数件なら許容できる」という判断に対して、やや多い。
それでもこの刻みを選んだのは、**閾値が設定シートで即座に変えられる**ためで、
運用の体感を見てから絞るほうが、机上で決めるより確実だと判断した。

## 却下した案

| 案 | 却下理由 |
| --- | --- |
| 1 段階のみ（5.2 件/日） | 最も静か。ただし大きく化けた商品が埋もれる |
| 500 / 2,000 / 5,000（6.8 件/日） | 通知量は減るが、初回と 2 段階目の間が空きすぎる |
| 実測から逆算した 7,300（1.4 件/週） | 週 2 件だけ鳴る水準。**取りこぼしが多すぎる** |
| 段階ごとではなく毎日再掲する | 同じ投稿が毎日届く。すぐ読まれなくなる |

## 影響

- [[UC-01]]: 通知済みの最大段階を通知ログで管理し、上回ったときだけ送る

**初回（500）にはラベルを付けない。** 3 段階なので再通知は必ず
1,000 か 2,000 で起き、印の無い通知は新着だと分かる。

## 見直しの条件

- 通知が多すぎて読まれなくなったとき（閾値を上げる）
- 週次サマリーの最大保存数が閾値に遠く届かない週が続くとき（閾値を下げる）
- 監視対象を変えたとき。**閾値は監視対象の規模に依存する。** 別のアカウントに
  同じ値をそのまま当てても意味を持たない
