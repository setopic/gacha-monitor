# X API からの投稿取得

## 境界

**外部サービスとの境界。** こちらから読みに行くだけで、相手から呼ばれることはない。
片方だけが古いまま動きうる（相手の仕様が変わってもこちらは気づかない）ので契約として扱う。

## 受け口

| 受け口 | 起動条件 | 実行できる人 | 対応するユースケース |
| --- | --- | --- | --- |
| 監視対象の投稿一覧 | 1 日 1 回の時刻起動 | 仕組みのみ（人は起動しない） | [UC-01](../30-usecases/uc-01-detect-and-notify.md) |
| 監視対象の識別子解決 | 識別子が設定シートに未記録のとき 1 回だけ | 仕組みのみ | [UC-01](../30-usecases/uc-01-detect-and-notify.md) |

## 入力

| 項目 | 型 | 必須 | 説明 | 由来（ドメイン） |
| --- | --- | --- | --- | --- |
| 監視対象の識別子 | 文字列 | ○ | 一覧を引く相手 | [DOM-01](../20-domain/dom-01-post.md) 監視対象 |
| 取得の開始時刻 | 日時 | ○ | 現在時刻から追跡期間を引いた時刻。**これより古い投稿は要求しない** | [DOM-01](../20-domain/dom-01-post.md) 追跡期間 |
| 1 回あたりの件数 | 整数 | ○ | 上限 100 | — |
| 続きの位置 | 文字列 | | 前回の応答が続きを示したときだけ付ける | — |

**取得の開始時刻で絞るのが費用の要。** 課金は返ってきた件数に対して発生するので、
広く取ってから捨てると、捨てた分まで払うことになる。

**関連情報の展開を要求しない。** 投稿者の情報などを一緒に要求すると、
1 件ごとに別枠の課金が加算される。必要なのは投稿ごとの指標だけ。

## 出力（成功時）

| 項目 | 型 | 説明 |
| --- | --- | --- |
| 投稿の配列 | 配列 | 開始時刻以降の投稿。**自作以外も混ざる** |
| 投稿 ID | 文字列 | [DOM-01](../20-domain/dom-01-post.md) 投稿 ID |
| 投稿日時 | 日時 | [DOM-01](../20-domain/dom-01-post.md) 投稿日時 |
| 本文 | 文字列 | [DOM-01](../20-domain/dom-01-post.md) 本文 |
| 参照している投稿 | 配列 | 転載・引用・返信の判定に使う。無ければ自作 |
| 指標 6 種 | 整数 | [DOM-02](../20-domain/dom-02-metrics.md) のとおり |
| 続きの位置 | 文字列 | まだ続きがあるときだけ返る |

## 失敗

| 状況 | 返すもの | 誰に見えるか | 対応する例外フロー |
| --- | --- | --- | --- |
| 認証が無効 | HTTP 401 | 担当者（異常通知） | [UC-03](../30-usecases/uc-03-alert-anomaly.md) E1 |
| 残高不足 | HTTP 402 | 担当者（異常通知） | [UC-03](../30-usecases/uc-03-alert-anomaly.md) E1 |
| 権限不足 | HTTP 403 | 担当者（異常通知） | [UC-03](../30-usecases/uc-03-alert-anomaly.md) E1 |
| 要求が多すぎる | HTTP 429 | 担当者（異常通知） | [UC-03](../30-usecases/uc-03-alert-anomaly.md) E1 |

**失敗した要求は課金されない。** データが返った成功時だけ課金される。

## 冪等性・整合性

**同じ投稿を 24 時間 UTC 以内に何度取得しても課金は 1 回。** これが
[ARCH-02](../10-architecture/arch-02-daily-batch.md) の実行モデルの前提になっている。ただし提供側は
「緩やかな保証」と断っており、厳密な保証ではない。

取得は読み取りのみで、相手の状態を変えない。何度呼んでも安全。

## 変更するときの影響

- **絞り込みの指定を外すと費用が跳ね上がる。** 追跡期間の外まで返ってきて、
  その全件に課金される
- **関連情報の展開を足すと、投稿の件数ぶんだけ別枠の課金が乗る**
- 応答から指標が消えた場合、[DOM-02](../20-domain/dom-02-metrics.md) の注目度が定義できなくなる。
  判定に使う指標の変更が必要になる（[ADR-0002](../50-adr/adr-0002-save-count-as-metric.md) の見直し）
