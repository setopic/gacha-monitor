# システム全体

## 解決したい構造上の問題

販売店は、これから発売される商品のうち**どれが混雑を招くか**を発売前に知りたい。
判断材料は SNS 上の反応しかないが、人が毎日タイムラインを追うのは続かないし、
「いつもより注目されている」の線引きが人によってぶれる。

**反応の量を毎日機械的に測り、閾値を超えたものだけを人に見せる**必要がある。
そのために必要な要素は 4 つで、どれも既存のサービスであり、
自前で運用するサーバは持たない。

## 構成

| 要素 | 責務 | 責務でないこと |
| --- | --- | --- |
| X API | 監視対象アカウントの投稿と、その反応の数を返す | 注目度の判定。どの投稿が重要かは一切関与しない |
| Apps Script | 毎日 1 回、取得・判定・記録・通知を順に行う | 常駐処理。イベントの受信口を持たない |
| スプレッドシート | 設定の保持と、測った値の蓄積 | 判定ロジック。関数や条件付き書式では判定しない |
| LINE 公式アカウント | 判定結果を担当者に届ける | 対話。問い合わせに答える窓口ではない |

## 境界

**受信する通信を持たない。** Webhook も API サーバも公開しない。
Apps Script が時刻起動で動き、外へ出ていくだけの一方向で完結する。

外部との境界は 2 つで、どちらも [[CON-01]] と [[CON-02]] が規定する。

- X API から読む（読み取りのみ。投稿しない）
- LINE へ送る（送信のみ。受信しない）

## 前提と制約

- **監視対象は公開アカウントの商品告知に限る。** 個人アカウントは扱わない。
  取得したデータを再配布しない
- **X API は従量課金で前払い。** 残高が尽きると静かに止まる（[[UC-03]] が検知する）
- **秘密情報はリポジトリに置かない。** 認証情報は Apps Script の
  スクリプトプロパティ、監視対象の指定は設定シートにある（[[CON-03]]）
- 監視対象は 1 アカウント。複数を扱う構造は持たない

## 未決事項

- 追跡期間を 4 日より延ばすべきかは、運用データが貯まるまで判断できない（[[ADR-0003]]）
